# Character and brand exploration

Use only for explicit project avatar/character/brand exploration. It does not change ordinary article defaults or enable persona/placement.

Diverge by separating user requirements, variable preferences, and assistant assumptions. Extract material/color/character-treatment aesthetics from references. Rejected old directions do not remain hard constraints. After the user chooses, fix 2–3 recognition features and compare bounded structural/material/density variables. Distinguish selected, acceptable alternative, and assistant recommendation; follow the latest user choice rather than a score.

Explain whether delivery crops a selected original or generates a separate high-resolution image. Regeneration may change identity and requires renewed confirmation. Interpolation does not create native detail. Prefer unnumbered generated concept boards with deterministic numbering afterward; check both for letter-like artifacts. A board crop proves a direction, not full-resolution final delivery.

For selected work preserve reference → prompt → source image → numbered board → selected region → export → checks. Unselected exploration need not all be archived. Binaries follow project assets/ignore policy; prompts/manifests/receipts belong to the article's text directory or project-declared evidence directory, never solely an ignored binary root.

Manifests record relative source/output paths, SHA-256, native dimensions, actual crop, padding/scaling, tools/necessary versions, and external reference permissions. Hash integrity is not retrievability: record local/CDN/backup availability. Move retainable temporary references to persistent assets; otherwise disclose incomplete reproducibility. Deterministic derivation from saved pixels differs from rerunning a model, which need not reproduce them.

Check square/circular crop at actual use size; avatars include 32/64/128px silhouette/recognition checks. GIFs need multiple frames, frame count, and duration; static preview is insufficient. Record unresolved defects rather than treating file existence/concept selection as acceptance.

Keep selection (who/when/version/alternatives), export (paths/hashes/treatment/checks), and adoption (storage/account/draft/phone evidence or unknown) separate in existing records. This is not another article state machine or progress file. Project control docs retain current choice/evidence pointers; platform component acceptance stays with its stage.
