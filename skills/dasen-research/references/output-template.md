# Topic candidate report

Load only for requested topic comparison, series planning, or timely-topic screening; ordinary fact research does not create this report. The Chinese template is audience-facing output.

```markdown
# 选题候选 · YYYY-MM-DD

> checked_at: YYYY-MM-DDTHH:MM:SS+08:00
> 实际后端：只写真取到数据的后端
> 数据口径：候选池 / 关键词命中 / 时间窗 / 失败平台

## 1. 选题判断

- **目标读者与场景**：谁在什么情况下遇到什么问题
- **本篇交付物**：读完能得到什么
- **成立依据**：2–3 条事实、平台信号或真实反馈，带来源 ID
- **差异化**：和已有内容相比增加什么
- **时效**：立即 / 本周 / 常青
- **来源风险**：单源、字段不可靠、尚未确认等
- **推荐组合**：`journey / length / method`
- **与系列关系**：验证假设 / 建立结构 / 扩展场景 / 复利更新 / 独立爆点

## 2. 选题判断

（同上）

## 推荐顺序

1. 首选：理由必须落到读者需求、可交付物和来源条件。
2. 次选：说明为什么暂不先做。
3. 放弃项：记录不成立或来源不足的原因。
```

Return 3–5 candidates, or three for quick, subject to available qualifying material. Do not impose emotional/suspense title formulas or a five-part outline; writing owns final titles/structure under brief/Style. Evidence needs a retrievable source locator. Merge similar topics rather than rephrasing to fill the count. Save as a research artifact or the series candidate queue; do not automatically start an article.
